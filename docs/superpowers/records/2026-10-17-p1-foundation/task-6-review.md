- **M1** `services/server/src/tassel/api/sessions.py:43, 54, 66`: the path parameter is `{session_id}` where the brief writes `{id}`. Behaviour is identical and the name is clearer, but it is part of the generated contract: Task 7's types will be keyed on `paths["/v1/sessions/{session_id}"]` with `params.path.session_id`. - **M2** `services/server/src/tassel/models.py:30-31`: `SessionPatch.type` and `.language` advertise `null` in the JSON schema (`anyOf [enum, null]`) while the server rejects `null` with 422, so the generated TypeScript will allow a value the API refuses. `SessionType | SkipJsonSchema[None]` (from `pydantic.json_schema`) keeps the omit-default and the after-validator but drops `null` from the schema. Fold in whenever `models.py` is next touched, or at Task 7 if the generated types look wrong.
- **M3** `services/server/tests/test_sessions.py:97, 193`: `last_activity_at` comparisons use `>` on the ISO strings. Pydantic omits the fractional seconds when the microsecond is exactly 0, and `"…:00Z" > "…:00.5Z"` is then lexicographically wrong, so the comparison can flip about once per million timestamps. `datetime.fromisoformat()` on both sides makes it exact.
